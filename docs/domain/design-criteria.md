# 분석 기준 데이터

> Agent가 판단을 내릴 때 참조하는 구체적 수치 기준입니다.

## 컨벤션 심각도 기준

| 규칙 | 심각도 | 왜 이 심각도인가 |
|------|--------|-----------------|
| bare except 사용 | error | 예상치 못한 예외를 삼켜서 디버깅 불가능하게 만듦 |
| 하드코딩 시크릿 | error | 보안 사고 직결. git history에 영구 노출 |
| eval() 사용 | error | 코드 인젝션 공격 벡터 |
| 함수 50줄 초과 | warning | 테스트/유지보수 어려움. 분할 권장 |
| print() 사용 | warning | 운영 환경에서 로그 레벨 제어 불가 |
| 타입 힌트 누락 | info | 코드 가독성 저하. IDE 자동완성 불가 |
| 매직 넘버 | info | 의미 파악 어려움. 상수 분리 권장 |

## 시나리오 검증 기준

| 항목 | 값 | 근거 |
|------|-----|------|
| 생성 시나리오 수 | 4~6개 | 3개 이하: 커버리지 부족. 7개 이상: 노이즈 증가 |
| 카테고리 구성 | 기능, 예외, 경계값, 보안 | 최소 2개 카테고리 포함해야 균형잡힌 검증 |
| pass 판정 기준 | 60% 이상 | 50%는 동전 던지기 수준. 70%는 unclear가 많을 때 너무 엄격 |
| 확신도 신뢰 기준 | 70 이상 | 70 미만은 LLM이 확신 없다는 의미. 판단 보류 권장 |

## 리스크 레벨 판정

| 레벨 | 점수 | 실제 의미 |
|------|------|-----------|
| Low (0~3) | 영향 모듈 1개 이하, API 변경 없음 | 자동 머지 고려 가능 |
| Medium (4~7) | 영향 모듈 2~3개 | 리뷰어 1인 확인 권장 |
| High (8~14) | 4개 이상 모듈 영향 또는 API 변경 | 시니어 리뷰 필수 |
| Critical (15+) | API 변경 + 보안/인증/DB 파일 변경 | 팀 리뷰 + QA 검증 필수 |

점수 산정:
- 영향 모듈 수 × 2 (최대 10점)
- API 변경 감지: +5점
- 핵심 파일 변경 (auth, payment, security, database, migration): +3점/파일

## LLM 호출 파라미터

| 용도 | 모델 | max_tokens | temperature | diff 제한 |
|------|------|-----------|-------------|----------|
| 컨벤션 검사 | gpt-4o-mini | 1,024 | 0.3 | 8KB |
| 시나리오 생성 | gpt-4o-mini | 1,024 | 0.3 | 전체 diff |
| 시나리오 평가 | gpt-4o-mini | 512 | 0.3 | 전체 diff |
| 도메인 설명 | gpt-4o-mini | 512 | 0.3 | 2,000자 |
| 비즈니스 영향도 | gpt-4o-mini | 1,024 | 0.3 | 4,000자 |
| 채팅 | gpt-4o-mini | 1,024 | - | N/A |

temperature 0.3인 이유: 분석 결과의 일관성이 중요. 창의적 답변보다 정확한 판단 우선.
