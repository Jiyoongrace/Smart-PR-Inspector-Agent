# 사용자 유형별 요구사항

> PR Inspector를 사용하는 사용자 유형과 각각이 기대하는 동작입니다.

## 시니어 개발자 (주 사용자)

- 핵심 니즈: "이 PR 머지해도 되나?" 빠른 판단
- 주로 보는 것: 영향도 분석 (어떤 모듈에 사이드 이펙트가 있는지)
- 사용 패턴: 워크플로우 노드 클릭 → 해당 분석 탭 → 승인/머지
- 만족 기준: 분석 60초 이내 완료, 리스크 레벨이 실제 위험도와 일치

## 주니어 개발자

- 핵심 니즈: "내가 뭘 잘못했고 어떻게 고쳐야 하나?"
- 주로 보는 것: 컨벤션 위반 상세 + 수정 제안 (suggestion 필드)
- 사용 패턴: 컨벤션 탭에서 위반 확인 → 채팅으로 수정 방법 질문
- 만족 기준: 위반 사항마다 구체적 수정 코드가 포함되어 있을 것

## 테크 리드

- 핵심 니즈: 팀 코드 품질 트렌드 파악, 위험한 PR 빠른 식별
- 주로 보는 것: 히스토리 탭, 리스크 high/critical PR
- 사용 패턴: Slack 알림으로 위험 PR 인지 → 웹에서 상세 확인
- 만족 기준: high/critical PR에 자동 Slack 알림, 컨벤션 준수율 추이

## DevOps 엔지니어

- 핵심 니즈: API 스펙 변경이 기존 클라이언트를 깨뜨리지 않는지 확인
- 주로 보는 것: 문서 탭 (Swagger 변경 감지)
- 사용 패턴: has_api_changes=true 알림 → 문서 탭에서 초안 확인
- 만족 기준: API 변경 시 반드시 Swagger 업데이트 제안 포함

## 분석 품질 SLA

| 지표 | 현재 | 목표 |
|------|------|------|
| 분석 완료 시간 | ~45초 | 60초 이내 |
| 컨벤션 탐지 정확도 | - | 90% 이상 |
| 시나리오 검증 유효성 | - | pass/fail 판정의 80%가 수동 리뷰와 일치 |
| SSE 이벤트 지연 | - | 노드 완료 후 2초 이내 |
| 가용성 | - | 99.5% (월간) |
